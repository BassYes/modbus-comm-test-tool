## 2. M3a：网卡配置与提权助手

### 2.1 权限与信任边界（AD-08）

```text
主程序（普通用户）
  ├─ 只读：NetworkInterface 枚举网卡（无需管理员）
  ├─ 校验：NetworkConfigValidator（纯函数：IP/掩码/网关格式、掩码连续、网关同网段、网络/广播地址、地址重复）
  ├─ 快照：应用前原子写 data/netsnap/<网卡>-<时间>.json（最多保留 20 份）
  └─ 写入：命名管道 → Comm.NetConfigHelper.exe（runas 提权，仅固定命令集）
                    ├─ 应用 + 回读校验
                    ├─ 不一致 → 自动回滚到快照
                    └─ 安全恢复倒计时（助手持有；主程序崩溃也会回滚）
```

- 助手只接受固定命令：`snapshot` / `apply` / `restore` / `add-aux` / `remove-aux` / `confirm` / `status` / `shutdown`；**任何其他字符串都被拒绝**（含 `cmd.exe /c ...` 这类注入尝试，已用测试覆盖）。
- 管道名一次性随机、按调用方进程号校验（规划 12.5）；空闲 5 分钟自动退出，但**倒计时武装期间不退出**。
- 助手是 WinExe（无控制台窗口，避免用户误关窗口导致回滚计时丢失）；诊断走 `logs/confighelper-*.log` 与 `--self-test` 报告文件。

### 2.2 界面（网络工具页）

- 左侧：子网计算（保留原有）→ **本机网卡配置**（可折叠，整体可滚动）：
  - 只读网卡列表（接口/状态/DHCP/地址数/描述）
  - 编辑区：静态 / DHCP、IPv4、掩码或前缀（`24`、`/24`、`255.255.255.0` 三种写法）、网关（留空＝不改）、DNS + “同时应用 DNS”、**“替换网卡上现有地址”**（取消勾选＝保留原地址，即辅助 IP 语义）
  - **校验并预览** → 显示规范化结果（网络地址/广播地址/主机范围）与风险提示；校验不通过时“应用配置”按钮禁用
  - **应用配置** → 二次确认（明确列出：会立即影响网络连接/远程会话可能断开、写操作由提权助手执行并弹 UAC、倒计时状态、目标网卡与将要写入的值）
  - **保留此配置**（倒计时进行中可点）与剩余秒数展示
  - 网卡现有地址列表 + 叠加/移除辅助 IP
  - 配置快照列表 + “恢复选中快照”；启动时若发现**未决快照**（上次未确认保留）会主动提示恢复
  - 网络配置方案（保存 / 载入 / 删除）与助手状态（是否就绪、预期路径、搜索顺序）
- 所有写操作都写诊断日志（`NetConfig/*`）；不记录任何凭据（本功能本身无凭据）。

### 2.3 与规划的诚实偏差

| 项 | 规划 | 实现 | 原因 |
|---|---|---|---|
| DHCP 切换与 DNS 改写 | 用 IP Helper（`CreateUnicastIpAddressEntry` 等）或 CIM | 静态地址/网关/辅助 IP 用 **IP Helper P/Invoke**；**DHCP 与 DNS 走 netsh（只看退出码，不解析文本）** | IP Helper 没有稳定的 DHCP 开关 API；CIM 需要额外程序集（离线环境不引入）。netsh 仅看退出码即满足 AD-07 的“系统语言无关”要求 |
| 回滚倒计时 | 默认关，勾选默认 60 s | 一致（默认关；勾选后默认 60 s，可选 15–3600 s） | — |

## 3. M3b：多会话工作区、插件宿主、工作区文件、架构测试

### 3.1 会话模型重构（R-16，规划 21.2.2）

| 层次 | 重构前 | 重构后 |
|---|---|---|
| 会话本体 | `SessionManager` 单会话（`_session`） | `SessionContext`（每会话独立：传输/事务/统计/默认 Unit ID/串口重配上下文/监视投影/监视表） |
| 会话集合 | 无 | `SessionManager` 作为**注册表**：`Sessions`、`Active`、`CreateSession`（上限默认 8，设置页可调）、`CloseSession`（至少保留 1 个）、`Activate`、`SessionsChanged` |
| 串口独占 | 无（仅靠系统占用报错） | `SerialPortRegistry` 按 `serial:COMx` 全局独占，抢占时给出**含占用者会话名**的可读提示；打开失败会释放登记（回归修复） |
| 页面 ViewModel | 全部单例，共享同一会话 | 每会话一组实例（`SessionWorkspaceViewModel`），构造函数注入 `SessionContext`；不再依赖 `SessionManager` 的转发成员 |
| 报文监视 | 全局单例 | **每会话一个 `MonitorService`**，按 `FrameRecord.SessionId` 过滤（`暂停显示` 仍是全局的：共用同一显示缓冲与投递节拍，与规划 4.6.3 一致） |
| 监视表 | 全局单例 | **会话作用域**（点位与采样记录只属于该会话） |
| 窗口 | 单窗口 | `SessionWindow`：会话工作区可**拆分到独立窗口**、**移回主窗口**；窗口位置/尺寸/最大化/显示器按会话持久化，显示器被移除时回到可见区域 |
| 关闭语义 | 关闭窗口即退出 | 关闭拆分窗口时三选一：**取消 / 保持会话并移回主窗口 / 取消任务并关闭会话**；主窗口用 `OnMainWindowClose` 退出，并先关闭所有会话窗口 |
| 全局页面 | 10 页全部单例 | 仅 网络工具 / 局域网扫描 / 扩展中心 / 设置与日志 为全局；其余为会话页 |

**可自动化验收证据**（`tools/Comm.SessionProbe`，23 项全部通过）：
两个会话并行连接同一目标并可同时扫描；两会话统计互不串扰；总线帧带各自 `SessionId`；每会话监视只显示自己的帧；同一串口第二个会话被拒且提示含占用者名称；会话上限拒绝并说明原因；最后一个会话不允许关闭；关闭后注册表同步；活动会话切换后状态栏可用。

**仍需人工验证**（见第 6 节）：真实 WPF 窗口的拆分/移回、多显示器与混合 DPI 下的布局恢复。

### 3.2 插件宿主（R-10，规划 8、14.7、15.11、AD-13）

- **发现**：只扫描 `<程序目录>/plugins/*/plugin.json`（受信目录；拒绝目录逃逸）。
- **清单校验**：`id`/`name`/`version` 必填、`hostVersionRange` 兼容性（支持 `*`、`>=0.2.0`、`>=0.2.0 <1.0.0`）、入口（`entry` 程序集 + `type` 类型，缺省时自动查找唯一实现）。
- **加载**：每插件一个 `AssemblyLoadContext`（可卸载）；**`Comm.Core` 与 `Comm.Plugins.Abstractions` 强制回落默认上下文**，保证 `ICommPlugin` 类型标识一致（插件目录里不放这两个程序集也能加载，已用测试覆盖）。
- **故障隔离**：注册调用有异常边界与超时（默认 5 s）；单插件连续失败 3 次自动禁用（`PLG-7005`），禁用状态与失败计数持久化到设置文件（下次启动仍禁用，直到手动启用）；单个插件失败不影响其他插件与主程序启动。
- **扩展中心页**：插件列表（Id/名称/版本/状态/能力/风险/错误原因）、启用/禁用/重新扫描、创建与打开插件目录、复制诊断信息，并显示已注册扩展点清单；界面明确写出“`AssemblyLoadContext` 不是安全沙箱，只装可信插件”。
- **参考示例插件** `samples/Comm.Plugin.Sample`：注册一个报文解析器（`sample-frame-summary`）与一个导出格式（`sample-tsv`），只读、不依赖 WPF；支持 `throw-on-register.flag` / `slow-register.flag` 两个自测标记用于验证宿主的异常边界与超时。

### 3.3 工作区/项目文件（规划 4.12、AD-10）

- `.ctws` 文件（`schemaVersion = 1`），包含：串口模板、TCP 模板、设备目标、扫描方案、报文模板、网卡配置方案、监视点位。
- 原子写入（临时文件 + 替换）；损坏文件保留 `<文件>.bad-<时间戳>` 备份并以空工作区启动；**文件版本高于当前程序时只读打开并拒绝覆盖**（不丢用户数据）。
- 导入支持两种语义：**替换** / **合并**（同 Id 以工作区为准，目标独有项保留）；日志、监视、扫描默认值等运行期设置**不受影响**。
- 设置页新增“会话与工作区”区：并行会话上限、启动时自动重开上次工作区、保存/打开/应用工作区、内容校验问题清单、窗口布局查看与清除。
- 监视点位是会话作用域的（多会话重构的直接结果），因此工作区里的点位在导入时只做保留与提示，由监视表页手工添加。

### 3.4 架构测试（规划 12.3、16.3.1）

`tests/Comm.Architecture.Tests` 共 15 个断言（纯静态 + 尽力而为的行为检查，无需 NetArchTest）：

## 6. 仍需人工验证的项（诚实清单）

> 与 M2.5 的第 5 节同一性质：这些项本机无法自动完成，已给出操作步骤，请在具备条件时回填结论。

| # | 项目 | 为什么本机未做 | 操作步骤 |
|---|---|---|---|
| 1 | **真实网卡写入**（UAC 提权、回读校验、失败回滚、倒计时到期自动恢复） | 本机不能改动网络配置（会中断开发环境），且需要交互式 UAC | 在隔离虚拟机（新加一块虚拟网卡）中：网络工具页 → 选中虚拟网卡 → 填静态地址 → 校验并预览 → 应用配置 → 同意 UAC → 核对回读值；勾选倒计时 60 s 且不点“保留”，确认到期自动恢复到原配置；再试一次并点“保留”，确认不再回滚；断开/杀主程序后助手仍应回滚 |
| 2 | 提权助手的 UAC 显示 | 需要真实提权 | 用正式证书签名后确认 UAC 显示“已验证的发布者”（R-20 的 M3a 项）；未签名时会显示“未知发布者”，属预期 |
| 3 | **拆分窗口的真实交互**（拆分/移回/关闭确认、多显示器、125%/150%/200% DPI、重启后位置恢复） | 需要交互式 WPF 窗口 | 启动程序 → 新建会话 → “拆分到新窗口” → 拖动到第二显示器并缩放 → 关闭该窗口选“移回主窗口” → 再拆分后选“取消任务并关闭会话” → 重启确认位置/尺寸/最大化被恢复；把窗口拖到已拔掉的显示器位置后重启，应回到可见区域 |
| 4 | **干净机冒烟**（M3 复验，规划 22.6.4） | 需要干净 Win10/Win11 虚拟机 | 用 `tools\Publish-App.ps1 -Sign -Zip` 的产物执行 M2.5 第 5 节清单；本次新增：网络工具页能读出网卡、扩展中心能列出 `plugins\Sample` 并显示“已加载”、`helper\Comm.NetConfigHelper.exe` 存在 |
| 5 | 真实硬件的网卡/串口组合下的 M3 复验 | 需要硬件 | 沿用 `tools/Invoke-HilProbe.ps1` 与 `docs/hardware-compatibility-matrix-v1.md` |
| 6 | 9 页之外的新页截图 | 截图脚本需人工触发 | `bash docs/capture-pages.sh --pages 8,9,10,11`（扩展中心为第 10 页） |

界面截图 `docs/screenshot-*.png` 目前仍是 M2.5 的 10 页版本；本次未重新生成（脚本与页面映射已更新），可在有 GUI 的会话中执行 `docs/capture-pages.sh` 刷新。

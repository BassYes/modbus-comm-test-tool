## 1. 为什么必须签名

用户看到的两个弹窗是不同机制，但根因相同（规划 22.5.1）：

| 弹窗 | 触发条件 | 签名后的表现 |
|---|---|---|
| “打开文件 – 安全警告：无法验证发布者” | 文件带 **MOTW**（`Zone.Identifier`）**且**未签名 | 变为“**已验证的发布者：xxx**”（是否仍弹出取决于来源区域与受信任发布者设置） |
| “Windows 已保护你的电脑（SmartScreen）” | MOTW + 未签名 + **无下载信誉** | 随信誉积累逐步消失；EV/云签名通常更快 |
| UAC 黄框“未知发布者”（M3a 的 `NetConfigHelper`） | 提权程序未签名 | 变为蓝框“已验证的发布者” |

**签名是必要条件**；安装包（L2）是“从下载到启动零提示”的最有效手段，便携包（L3）仍可能出现“已验证的发布者”提示。

## 2. 已交付的签名流水线（M2.5）

```powershell
# 1) 开发自签名证书（本机联调用；不需要管理员权限）
.\tools\New-DevCodeSigningCert.ps1

# 2) 签名单个文件
.\tools\Sign-App.ps1 -Path .\artifacts\publish\CommTestTool.exe -TimestampServer http://timestamp.digicert.com

# 3) 发布 + 签名 + 打包（默认自包含；对本项目 11 个自有 exe/dll 全部签名）
.\tools\Publish-App.ps1 -Sign -Zip -TimestampServer http://timestamp.digicert.com
```

- 时间戳（RFC3161）**必须带**：否则证书过期后签名失效。
- `Publish-App.ps1` 会自动附带 `便携包说明.txt` 与 `解除锁定-便携包.ps1`。
- 装 Windows SDK 后可把 `Set-AuthenticodeSignature` 换成 `signtool sign /fd sha256 /tr <ts>`，参数语义一致。

## 3. 三种证书来源对比

| 方案 | 典型成本 | 私钥形态 | SmartScreen 表现 | 适用场景 |
|---|---|---|---|---|
| **商业 OV 代码签名证书** | 约 ¥1500–3000/年 | 按 CA/B 要求（2023 起）必须是**硬件令牌或云 HSM**，**不能把 `.pfx` 放进 CI** | 需累积下载信誉，初期可能仍弹 | 对外分发 |
| **商业 EV 代码签名证书** | 约 ¥2500–5000/年 | 硬件令牌 / 云 HSM | 通常立即获得信誉 | 对外分发、希望尽快“干净” |
| **Azure Trusted Signing（云签名）** | 约 $9.99/月起 | 云 HSM，CI 内直接签 | 与 EV 接近 | 已有可验证组织历史的团队 |
| **内部自签名 / 内部 CA** | 0 | 自管（可导出） | 仅对已导入根证书的受控电脑有效 | 开发联调、域内分发（L4） |

> 价格与政策以厂商最新报价与微软/CA 最新规则为准，**本表仅供参考**。
> 关键提醒：**新证书也可能有一段信誉积累期**，SmartScreen 信誉与证书类型、下载量、发布者一致性都有关，需在测试机上实测。

## 4. 需要项目负责人回答（Q-1）

1. 选哪种来源？预算上限？（建议：对外分发优先 **Azure Trusted Signing** 或 **OV**；若要求尽快“干净”则 **EV**）
2. 实名主体是谁？（企业/事业单位全称、统一社会信用代码、可接收验证电话的联系人）
3. 私钥如何保管？（云 HSM / 专用签名机 + 硬件令牌；**禁止**把私钥或 `.pfx` 提交进仓库或放进 CI 变量之外的明文文件）
4. 采购与实名审核通常需要 **数天到数周**，是否现在启动？

## 5. 采购与落地步骤（定案后）

1. 提交申请与实名材料 → 完成电话/邮箱核验（数天）。
2. 按选定方案完成私钥托管：
   - **云签名（推荐）**：在 CI 中用服务主体凭据直接调用签名 API；本机用一次性令牌。
   - **硬件令牌**：在**专用签名机**上插入令牌签名，签名机不接入日常办公网络。
3. 用正式证书重跑 `Publish-App.ps1 -Sign -Zip`，并验证 `signtool verify /pa /v` 或 `Get-AuthenticodeSignature` 为 `Valid`。
4. 按 `docs/security-warning-matrix.md` 在干净 Win10 22H2 / Win11 上逐渠道验证并截图存档。
5. 向微软提交样本核验以减少 Defender 误报：<https://www.microsoft.com/en-us/wdsi/filesubmission>
6. 记录证书主体、指纹、有效期与续期负责人（到期前 60 天提醒）。

## 6. 除签名之外必须同时做的事（已交付）

- **补全版本资源**：Company / Product / FileVersion / Copyright / 应用图标 —— 无版本信息的未知程序更容易被拦（X-3、X-9）。
- **不加壳、不压缩**（不使用 UPX 之类），默认**不使用“单文件自解压”**形态（解压到临时目录易触发启发式）。
- **提供签名安装包**（M4）：安装出来的文件不带 MOTW，之后启动不再弹“打开文件 – 安全警告”。
- **便携包如实说明**：随包提供 `解除锁定` 脚本与文字说明，不夸大“绝对不弹”。
- **不要求用户关闭** SmartScreen、UAC 或杀毒软件，也**不通过脚本偷偷写入排除项**。
- 保持**同一发布者名、同一文件名、同一发布地址**，信誉才会累积。

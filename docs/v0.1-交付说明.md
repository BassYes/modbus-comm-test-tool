## 3. 与规划文档的偏差及原因

| 偏差 | 原因 |
|---|---|
| 可执行文件名 `CommTestTool.exe`，界面标题为“通讯测试工具” | 中文程序名在部分构建、签名与安全软件链路中易出问题；如需中文文件名，发布时重命名即可，不影响功能 |
| 额外提供 `tests/Comm.TestRunner` 轻量运行器 | 本机 VSTest 的 testhost 被拒绝访问父进程句柄（`Win32Exception (5)`），无法用 `dotnet test` 完成自检；运行器执行同一批 xunit 用例，正常环境仍推荐 `dotnet test` |
| `Comm.Platform.Windows` 项目未创建 | 该项目服务于网卡配置（M3），v0.1 无对应功能 |
| 数据/日志目录暂用程序同级 `data/` 与 `logs/` | 与规划 12.7 的便携形态一致；安装版形态在打包阶段处理 |
| Serilog 未引入，改用自实现的日志闸门 | 规划 AD-09 要求“关闭时不创建文件”，自实现更容易精确控制该语义与滚动/保留策略；对外仍通过 `ILogger` 抽象（`Comm.Diagnostics.LogGateLoggerProvider`） |
| 未使用记录/回放通道 `ReplayChannel` | 规划将报文文件回放列为 v1.x |

## 4. 验证情况

### 4.1 自动化测试

- 113 个用例，全部通过；连续 3 次运行结果一致。
- 覆盖内容见 README 第 4 节。重点验证的行为：
  - 扫描类任务不产生任何写功能码请求（规划约束 CC-6）；
  - 未确认写请求被事务层守卫拒绝（错误码 `VAL-4004`），广播写需专项确认（`VAL-4005`）；
  - RS-485 回显被识别为 `ECHO` 且不影响请求配对；
  - 校验错误被视为可重试的通信噪声，且不会因为线上噪声丢掉随后到达的有效响应；
  - 数据解码在四种字节序下的正确性（含 Float32/Float64 与 NaN 识别）。

### 4.2 界面验证

- 程序可正常启动并渲染全部 7 个功能页（截图见 `docs/`）。
- 启动后 `logs/` 目录为空（日志开关关闭时确实不落盘）；无崩溃报告生成；内存环形日志在设置页可读。
- 已修复验证中发现的问题：标题栏与日志开关重叠、未检测到串口时端口框为空、窗口默认尺寸偏大。

### 4.3 尚未验证的部分（需真实硬件）

- 真实 USB-RS485/RS232 适配器上的回显识别与拆帧表现（当前用模拟器与回环通道验证逻辑）。
- 不同厂商设备的响应延迟、最大请求数量与地址基准差异。
- 长时间连续运行（规划要求 24 h）与 1000 帧/s 吞吐下的界面表现。

## 5. 现场验证步骤建议

1. 用一块 USB-RS485 适配器接一台已知从站设备，按 README 第 7 节顺序操作。
2. 打开“Debug 日志”，把 `日志级别` 设为 `Debug`，核对日志中是否包含会话参数、扫描参数、超时与校验错误统计。
3. 在报文监视页勾选/取消“报文解析”，确认解析开关不影响通信与落盘。
4. 手工发一帧 `01 03 00 00 00 01`（不含 CRC），点“自动填入校验位”，确认应得 `01 03 00 00 00 01 84 0A`，再发送并核对响应。
5. 故意发送写报文，确认出现写操作二次确认对话框。

## 6. 后续建议（按性价比排序）

1. **M2 寄存器定位**：现场“知道数值、不知道地址”的场景最耗时，`DataDecoder` 与扫描器已可直接复用。
2. **M2 局域网设备扫描**：子网计算与 `NetworkAdapters` 已就绪，补 ARP/ICMP/TCP 探测即可。
3. **真实硬件回归 + 24 h 稳定性**：先把已知适配器/设备的兼容性矩阵跑通，再考虑新增功能。
4. **M3 网卡配置与提权助手**：涉及现场网络变更风险，建议在 M2 完成后再做，并按规划 15.8 实现快照与回滚。
5. **发布工程化**：代码签名、单目录自包含发布、安装包与中文程序名（如需要）。

## 7. 已知风险

| 风险 | 影响 | 缓解 |
|---|---|---|
| 静默判定阈值在部分适配器上偏小或偏大 | 未知功能码帧可能被拆错 | 阈值可配置（会话设置），默认 5 ms；常见功能码走长度预测不依赖静默 |
| 回显抑制对写功能码不生效 | 回显的写请求会作为响应处理（字节相同，数据结果正确，但耗时统计偏小） | 已在 README 与代码注释中说明；如需更严格可在后续版本引入“回显窗口 + 双帧判别” |
| 显示缓冲上限为 200 000 条 | 长时间高频通信时界面只保留最近记录 | 记录到 JSONL 文件不丢，界面有丢弃计数提示 |
| 未做签名 | 首次运行的安全提示 | 现场可先在测试机确认，或后续补签名 |
